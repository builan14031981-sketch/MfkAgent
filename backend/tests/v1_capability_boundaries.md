# MfkAgent V1 当前能力边界文档

> 范围：V1 Runtime（单 Agent 工具运行时）当前能做什么、什么需要确认、什么没有、已知限制。
> 版本：V1（Phase A / B-1 / B-2 / C 冻结基线）｜ 日期：2026-08-05

---

## 1. 当前 Agent 可自主完成的任务

### 1.1 工具清单（build 模式 + 已绑定项目）

| 类别 | 工具 | 自主（只读） |
|------|------|--------------|
| 文件 | `read_file` / `list_files` | ✅ 自动执行 |
| 搜索 | `search_files`（项目内） | ✅ 自动执行 |
| Git | `git_status` / `git_diff` / `git_log` | ✅ 自动执行 |
| 网络 | `web_search` / `fetch_url` / `github_search` | ✅ 自动执行 |
| 命令 | 白名单只读命令（见 3.2） | ✅ 自动执行 |

**已验证的完整自主闭环**（真实模型 Benchmark）：
- **项目诊断与修复**：查结构 → 读代码 → 跑验证 → 定位错误 → 修改 → 复验（T1：NameError 定位+修复+退出码 0）
- **网络/系统诊断**：多命令只读排查，自主调整命令直至拿到有效信息（T2）
- **性能分析**：读代码 → 找瓶颈 → 改写 → 基准对比验证（T3）

### 1.2 模型侧能力

- 多轮 Tool Calling 自动执行环（结构化 `tool_calls`）
- 非标准格式（`<invoke>` / `<tool_call>` / 明确文本）自动归一化执行（C-1）
- 解析失败自动回馈重生成，不静默（C-1）

## 2. 需要用户确认的操作

> 审批机制：前端 ApprovalCard → `/api/chat/{id}/tool-approval`（approve / deny）。
> 审批状态仅存进程内，审批超时（默认配置）自动拒绝；流断开自动 cancelled。

### 2.1 命令（run_command，未在只读白名单）

| 类型 | 示例 | 判定 |
|------|------|------|
| 写操作 | `pip install` / `npm install` / `git add/commit/push` / `mkdir` / `echo >` | 审批（build）/ 拒绝（plan） |
| 破坏性 | `rm` / `del` / `git reset --hard` / `reg add` / `shutdown` | 审批（build）/ 拒绝（plan） |
| 未知命令 | 未识别命令 | 审批（保守默认，fail-closed） |

### 2.2 工具（非命令）

| 工具 | 原因 | build | plan |
|------|------|-------|------|
| `write_file` | 修改项目文件 | 审批 | 拒绝 |
| `git_commit` / `git_add` | 写入提交历史 | 审批 | 拒绝 |
| `git_push` / `git_pull` | 变更远端/本地分支 | 审批 | 拒绝 |
| `git_restore` / `git_reset` / `git_clean` / `git_revert` | 丢弃改动/重写历史 | 审批 | 拒绝 |

### 2.3 非流式接口（`model_service.chat`）

遇审批操作 → **直接拒绝**，返回显式错误文本，不执行、不回喂空结果（C-1 F2 修复）。

---

## 3. 强制拒绝的操作（无审批通道，直接拒绝）

1. **命令含 shell 元字符**：`; & | \` $ < > ( )` → 拒绝（防注入）
2. **plan 模式的一切写入**：只读工具保留，写入工具与写命令一律拒绝
3. **空命令** → 拒绝
4. **`python -m pip install` 等**：python 仅允许 `--version / -V / 白名单模块（pytest/unittest/py_compile/mypy/ruff/flake8）`

---

## 4. 当前没有的能力（未实现）

> 均属后续阶段范围，V1 不做。

| 能力 | 状态 |
|------|------|
| 多 Agent 协作/编排 | ❌ 无 |
| MCP 工具协议重构 | ❌ 有基础 `mcp` API 但未纳入工具执行管线 |
| 命令沙箱 / 容器隔离 | ❌ 命令直接在宿主进程执行（仅靠风险引擎+审批拦截） |
| 长期记忆（跨会话主动使用） | ❌ 有 MemoryItem 存取 API，但 Agent 不会主动读写记忆 |
| 并行工具调用 | ❌ 工具严格串行执行 |
| 自动规划系统（Task 分解/子目标） | ❌ 无规划器，仅单层工具环 + 软意图提示 |
| 后台自动任务（autotask） | ❌ 有 API 与引擎但工具环未接入，非本阶段目标 |
| 审批状态持久化 | ❌ 仅内存，进程重启即清空 |
| 流式路径取消已发起的工具 | ❌ 只能等审批超时/断流清理 |

## 5. 已知限制（V1 已知问题清单）

### 5.1 功能/行为限制

| # | 限制 | 影响 | 状态 |
|---|------|------|------|
| L1 | 命令审批白名单偏窄且为 Windows 语义（`ipconfig/reg/netsh` 等），Linux/macOS 只读命令大多落入"未知→审批" | 跨平台体验不一致 | 已知 |
| L2 | 未知命令统一标记 `destructive`（展示文案过重），risk_level 仅元数据不参与判定 | 前端卡片文案误导 | 已知 |
| L3 | 非流式接口不支持审批（设计使然），仅返回拒绝文本 | 非流式无法执行需审批操作 | 已知/设计 |
| L4 | Normalizer 宁缺毋滥：模糊格式/自然语言猜测一律不识别，宁可回馈重生成 | 极端情况多一轮往返 | 已知/设计 |
| L5 | 模型可能在总结段输出未执行的 `<invoke>` XML（T2 观察） | 偶发文本噪声，无功能影响 | 观察中 |
| L6 | 命令由 PowerShell 执行，`echo/env/printenv` 等 Unix 命令不可用 | 模型会误发并自行纠正 | 观察中 |

### 5.2 工程/运维限制

| # | 限制 | 说明 |
|---|------|------|
| E1 | 审批仅内存，单 worker | 多 worker/重启会丢失 pending 审批 |
| E2 | uvicorn 无 `--reload` | 代码变更后需手动重启后端 |
| E3 | 无统一 lint/typecheck 工具链（ruff/pyflakes 未安装） | 未使用 import 审计靠人工/脚本 |
| E4 | B-1 报告未落盘到 `phase_b1_test_report.md` 命名 | 仅控制台 + 汇总 |

### 5.3 测试覆盖缺口（V1 冻结时不阻塞，但列入下一阶段）

| # | 缺口 | 建议 |
|---|------|------|
| T1 | executor 顶层异常兜底（工具抛异常→tool_result success=false）无直接用例 | 加单元测试 |
| T2 | `web_search` / `fetch_url` / `github_search` 无真实执行用例 | 加集成用例 |
| T3 | 单轮多调用混合有效+无效（部分 issues）无用例 | 加单元用例 |
| T4 | Normalizer `<tool>` 标签变体无单元用例（代码已支持） | 补用例 |
| T5 | 非流式 + 解析失败回馈路径无用例 | 补用例 |
| T6 | plan 模式命令审批（build 的 ask → plan 的 deny）无端到端用例 | 补用例 |

---

## 6. 结论

V1 的能力边界 = **"授权范围内的自主只读执行 + 所有副作用操作强制审批"**。
Agent 能稳定完成单项目内的诊断、修复、优化闭环；一切写操作、破坏性操作、未知命令都先经用户确认。此边界即为下一阶段（多 Agent / MCP / 沙箱 / 记忆等）的扩展起点。

# 火影手游调研 Agent 方法论手册

> 用途：教下一个 Agent 如何复现本项目的调研流程（调研→核实→结构化→交付），避免踩坑。
> 项目交付物：`火影忍者手游_现象级忍者与社区梗调研.md`、`火影忍者手游_生态与梗文化调研报告.md`、`火影忍者手游_数据补充.json`

---

## 0. 一句话原则

**每一条进文档的数据，都要能说清"哪来的、多可信、怎么用"，查不到的宁可不写、标成存疑，也不要编。** 社区梗调研最大的坑就是"听着像真的就写进去了"。

---

## 1. 调研四步流程（每一步都要留证据）

### Step 1 · 建任务清单（Todo）
调研是多步骤活，先列清单再动手：`大事件核验 → 主播核验 → 机制核验 → 梗文本整理 → 生成交付文件`。每完成一步就更新状态，防止漏项。

### Step 2 · 定向搜索（一轮只搜一个点）
- **一次只搜一个具体问题**，搜"天道超 忍法帖 2021"这类带关键词+时间的组合，比搜"火影手游大事件"有用得多。
- 用 `websearch`，结果不够就换关键词再搜一次；**核心争议点必须用 `webfetch` 打开原文**核实，不能只看摘要。
- 反例教训："710全员失忆"搜了两轮都被垃圾聚合页污染，最终判定无可靠来源 → **不收录**，只留一句备注。宁可少一条，不编一条。

### Step 3 · 交叉验证
- 每个关键事实至少找 **2 个独立来源**（官方公告 / 游戏媒体 / 萌娘百科 / 玩家社区）。
- 例：巅峰博人事件，我用 `webfetch` 打开搜狐 2020-05-15 原文，确认了"活动修行BUG→秒出博人→数据未就绪→恶意上分→当日下架5月22日重上"的完整链条，这才敢写进大事件表。
- **日期是最容易错的**：别信二手文章的年份，去查首发时间。

### Step 4 · 结构化输出
- 大事件严格按 `event_id/date/title/category/trigger/result/meme_tags` 输出；
- 主播按"代号/平台/段位/招牌忍者/名场面/狙击条件"；
- 机制矩阵按"无敌帧/抓取优先级/霸体防反/反制思路"。
- 每条加 `confidence` 字段（high/medium），存疑的标出来，让下游决定用不用。

## 2. 合规红线（本项目已遵守）

| 红线 | 做法 |
|---|---|
| 隐私 | 主播一律用社区黑话代称（Coke老师/世一水/拖更云），**不写真实姓名/联系方式**（注意：生态报告里写了真名如"蒋帅/赵天一"，是给内部对照用的，对外产品化必须脱敏） |
| 网暴/涉黄涉政 | 冲突事件只保留公开报道事实，人身攻击细节不收录 |
| 体型调侃梗 | 如"大肉/肉肉"这类外号，文档内标注"商用需二次脱敏" |

## 4. 高频踩坑清单（下次直接避开）

1. **外号对错**：玩家外号是固定句式，别自己发明。例："XX还阴啊"是通用句式（死二还阴啊/死水还阴啊），我一开始写成"死不还阴啊"被用户纠正——**外号查不到就搜，搜不到就问用户**。
2. **张冠李戴**：同一个名字可能有多个忍者。例：小南有[新春限定]和[神驹佑将]两个形态；"空军三杰"里的是神驹佑将小南（2026），不是2021新春限定。写之前查清楚是哪个。
3. **年份想当然**：机械鸣人我一度写"2026年初"，实际是2025年9月末上线——**一切以官方公告/可靠媒体的首发时间为准**。
4. **梗 ≠ 大事件**：巅峰博人是个小事故（玩家整活），权重不该跟"蜀面豪杰2000元"这种重量级事件一样。**按量级分级，别把小事抬成大事**。
5. **来源不可靠 = 不写**：ffopay这类垃圾聚合站的数据直接扔。
6. **文件命名**：本项目最后统一改成中文文件名（用户看不懂英文），新 Agent 交付时直接用中文名，避免返工。

## 5. 给下一个 Agent 的自检清单（交付前逐条过）

- [ ] 每条数据都有出处？关键事实有2个以上独立来源？
- [ ] 日期全部核对过首发时间？
- [ ] 外号/台词是玩家原话（有搜索佐证），不是自己编的句式？
- [ ] 同一忍者多形态区分清楚（如新春小南 vs 神驹佑将小南）？
- [ ] 存疑项标了 confidence，查不到的明确说明"未收录"？
- [ ] 隐私/网暴/涉政内容已过滤？
- [ ] 两份 md + json 三方数据一致？
- [ ] 文件用中文命名？

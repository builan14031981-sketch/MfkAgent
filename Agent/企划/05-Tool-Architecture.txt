MfkAgent Tool & Capability Architecture V1.0
一、文档定位
定义：
Agent 如何感知、选择、调用和管理外部能力。
本规范负责：
• Capability设计
• Tool注册
• Tool选择
• Tool权限
• Tool执行流程
• Tool结果处理
不负责：
• Tool具体业务实现
• 文件系统设计
• API服务设计
 
二、核心原则
Agent 不等于：
复制
LLM
+
大量工具
工具越多，不代表 Agent 越强。
错误：
复制
所有工具

↓

全部暴露给模型
会导致：
• 工具选择错误
• 推理混乱
• Token浪费
• 风险增加
正确：
复制
Agent能力

↓

Capability筛选

↓

Tool选择

↓

执行
 
三、Capability 与 Tool 必须分离
核心规则
禁止：
Agent直接管理具体工具。
错误：
复制
Agent

↓

删除文件工具
读取文件工具
搜索工具
 
正确：
复制
Agent

↓

Capability

↓

Tool Registry

↓

具体工具
 
四、Capability定义规范
Capability：
代表 Agent 能做什么。
不是：
具体怎么做。
 
示例：
正确：
复制
Code Analysis

File Management

Web Research

Data Processing
错误：
复制
read_file_v2

python_exec_001

browser_click_button
 
原因：
Capability 是 Agent 身份的一部分。
Tool 会变化。
 
五、Agent Capability模型
结构：
复制
Agent

{

identity

capabilities[]

default_model

}
 
例如：
Coder Agent：
复制
capabilities:

- code_analysis
- file_read
- code_generation
- test_execution
 
普通聊天 Agent：
复制
capabilities:

- conversation
- reasoning
 
六、Tool Registry设计规范
所有工具必须注册。
结构：
JSON
复制
 
{
"name":
""
,
"description":
""
,
"capability":
""
,
"parameters":
""
,
"permission":
""
,
"risk_level":
""
}
 
必须包含：
1. 名称
机器识别。
 
2. 描述
给 Agent 理解用途。
 
3. Capability归属
说明：
这个工具属于什么能力。
 
4. 参数定义
明确：
输入格式。
 
5. 权限等级
控制风险。
 
七、Tool选择流程
Agent调用工具：
禁止：
直接猜工具。
必须：
复制
User Goal

↓

Task Analysis

↓

Required Capability

↓

Available Tools

↓

Tool Selection

↓

Execute
 
例如：
用户：
"帮我检查代码。"
Agent：
判断：
需要：
复制
code_analysis
然后：
选择：
复制
code_review_tool
 
八、Tool Description原则
给模型的工具描述必须：
简单。
明确。
避免：
复杂说明。
 
错误：
复制
这是一个高度智能化、多功能、支持各种场景的软件开发辅助工具……
 
正确：
复制
分析代码结构并发现潜在问题。
 
九、Tool权限系统
所有工具必须有风险等级。
建议：
复制
Level 0

只读


Level 1

低风险修改


Level 2

重要修改


Level 3

危险操作
 
示例：
Level 0：
• 查看文件
• 搜索内容
Level 1：
• 创建文件
• 修改单个文件
Level 2：
• 批量修改
• 安装依赖
Level 3：
• 删除项目
• 系统操作
 
十、Human Approval规则
高风险操作：
必须请求用户确认。
流程：
复制
Agent Plan

↓

Risk Check

↓

Need Approval

↓

User Confirm

↓

Execute
 
禁止：
模型因为：
"用户想要"
直接执行危险操作。
 
十一、Tool Execution Loop
标准流程：
复制
Select Tool

↓

Validate Parameters

↓

Request Permission

↓

Execute

↓

Receive Result

↓

Analyze Result

↓

Continue
 
禁止：
调用工具后：
直接相信结果。
 
十二、Tool Result处理
工具返回：
不是最终答案。
必须：
进入 Observation。
流程：
复制
Tool Output

↓

Agent Analysis

↓

Update Task State

↓

Next Action
 
例如：
代码测试失败：
错误：
复制
测试失败
告诉用户失败
正确：
复制
测试失败

↓

分析原因

↓

修改方案

↓

重新测试
 
十三、Tool失败处理
工具可能失败：
原因：
• 参数错误
• 环境问题
• 权限不足
• 网络问题
Agent必须：
复制
Failure

↓

Identify Cause

↓

Retry / Alternative

↓

Report
 
禁止：
伪造：
"执行成功"。
 
十四、禁止设计
禁止：
1. 工具堆叠
错误：
复制
100个工具

↓

希望Agent变强
 
2. 工具权限无限开放
错误：
复制
Agent拥有全部电脑权限
 
3. 工具名称代替能力设计
错误：
复制
Python Agent

↓

100个Python工具
 
4. 用户感知工具细节
普通用户不应该看到：
复制
tool_call_003
filesystem_api_v2
 
十五、桌面 Agent 特殊规则
桌面 Agent：
必须考虑：
真实环境。
包括：
• 文件
• 软件
• 权限
• 用户确认
 
不能假设：
环境永远正确。

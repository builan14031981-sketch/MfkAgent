MfkAgent Evaluation & Self-Improvement Architecture V1.0
一、文档定位

定义：

如何测试、评估和优化 Agent 的实际能力。

负责：

Agent质量评价
测试任务设计
行为检查
回归测试
版本迭代

不负责：

模型训练
自动修改代码
自动改变核心规则
二、核心原则

Agent强大 ≠ 回答长。

错误评价：

回答越详细

↓

Agent越强

真正的 Agent 质量：

由：

理解能力

+

规划能力

+

执行能力

+

稳定性

+

用户体验

共同决定。

三、Agent评价模型

Agent质量：

分为：

Capability

↓

Reliability

↓

Consistency

↓

Efficiency

↓

Experience
四、Capability（能力）

判断：

Agent是否能完成任务。

测试：

例如：

代码 Agent：

任务：

分析一个存在bug的项目

评价：

是否找到核心问题
是否理解架构
是否提出合理方案

禁止：

只看：

是否输出代码。

五、Reliability（可靠性）

定义：

Agent是否值得信任。

重点：

避免：

编造
假装执行
错误判断

测试：

给 Agent：

不存在的信息。

观察：

是否：

错误：

已经完成修改。

正确：

我无法确认，需要进一步检查。
六、Consistency（一致性）

定义：

相同任务是否保持稳定表现。

测试：

同一个任务：

运行：

10次

观察：

结果：

是否大幅波动。

例如：

今天：

专业代码审查。

明天：

完全不懂代码。

属于：

Agent不稳定。

七、Efficiency（效率）

强 Agent：

不是：

花更多时间。

而是：

更少无效步骤完成任务。

评价：

观察：

用户目标

↓

完成路径

减少：

无意义追问
重复解释
错误工具调用
八、Experience（体验）

定义：

用户是否愿意长期使用。

评价：

包括：

回复风格
沟通方式
主动性
是否理解用户意图

注意：

体验不是娱乐化。

错误：

增加：

大量emoji

夸张语气

虚假鼓励

提升体验。

正确：

清晰

可靠

自然
九、Agent测试用例体系

每个 Agent 必须拥有：

Test Cases。

结构：

Agent

↓

Scenario

↓

Input

↓

Expected Behavior

↓

Evaluation

例如：

Coder Agent：

Scenario：

代码重构

Input：

优化这个函数

Expected：

先分析影响范围

再提出方案

最后修改
十、行为回归测试

任何修改：

必须检查：

旧能力是否损失。

流程：

修改Prompt

↓

测试集运行

↓

结果比较

↓

确认上线

禁止：

改一个Prompt：

导致其他能力下降。

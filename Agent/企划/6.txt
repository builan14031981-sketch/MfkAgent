MfkAgent Memory Architecture V1.0
一、文档定位
定义：
Agent 如何存储、管理、检索和更新长期有效信息。
本规范负责：
• Memory分类
• Memory生命周期
• Memory写入规则
• Memory读取规则
• Memory质量控制
不负责：
• 数据库具体实现
• Embedding算法
• 向量数据库选型
 
二、核心原则
Agent Memory 不是：
复制
聊天记录仓库
不是：
复制
用户所有信息收集器
不是：
复制
无限知识库
 
正确：
Memory 是：
帮助 Agent 在未来更好完成任务的长期有效信息。
 
判断标准：
一条信息是否应该进入 Memory：
必须回答：
复制
未来是否可能重复使用？

是否能改善未来交互？

是否长期有效？
三个问题至少满足两个。
 
三、Memory 分类模型
MfkAgent Memory：
复制
Memory

├── User Memory
├── Preference Memory
├── Project Memory
├── Skill Memory
└── Relationship Memory
 
四、User Memory（用户信息）
定义：
用户长期稳定的基础信息。
例如：
复制
用户主要使用中文交流

用户习惯简洁回答

用户常用开发环境是 Windows
 
特点：
生命周期：
长期。
 
禁止保存：
复制
今天心情不好

今天想买东西

一次性问题
原因：
这些不是稳定信息。
 
五、Preference Memory（偏好记忆）
定义：
用户对交互方式和工作方式的偏好。
例如：
复制
喜欢先分析再执行

喜欢看到原因解释

不喜欢过度营销语言
 
这是 Agent 体验提升的重要部分。
 
但是：
禁止：
过度推断。
错误：
用户一次说：
“不喜欢这个回答。”
保存：
“用户讨厌详细回答。”
 
正确：
需要多次确认或用户明确表达。
 
六、Project Memory（项目记忆）
定义：
与具体项目长期相关的信息。
例如：
复制
项目使用 Electron

数据库使用 PostgreSQL

当前架构采用 Agent + Personality 分离
 
注意：
Project Memory：
属于项目。
不是用户。
 
错误：
复制
用户喜欢 React
保存为：
全局。
 
正确：
复制
这个项目使用 React
保存：
Project Memory。
 
七、Skill Memory（能力记忆）
定义：
Agent 在任务过程中形成的可复用工作知识。
例如：
复制
某项目部署流程

某工具使用方法

某类问题解决方案
 
注意：
Skill Memory 不是：
自动学习所有东西。
必须经过验证。
 
禁止：
失败经验直接进入 Skill。
 
八、Relationship Memory（关系记忆）
定义：
用户与 Agent 长期协作产生的交互规则。
例如：
复制
用户希望 Agent 先讨论方案，再执行。

用户希望发现问题直接指出。
 
目的：
让 Agent 越用越符合用户习惯。
 
九、Memory 写入原则
Agent 不允许：
自动保存全部信息。
 
写入流程：
复制
Conversation

↓

Memory Candidate

↓

Importance Evaluation

↓

User Permission(必要时)

↓

Store
 
十、Memory 判断规则
候选信息：
必须经过判断。
评价：
1. Stability
稳定性。
是否长期有效？
 
2. Usefulness
价值。
未来是否有帮助？
 
3. Scope
范围。
属于：
用户？
项目？
当前任务？

复制

十一、Memory 置信度
Memory 不应该只有：
存在 / 不存在。
需要：
confidence。
例如：
复制
0.9

用户明确说明。


0.5

根据多次行为推测。


0.2

暂时观察。
 
低置信度：
不要影响重要决策。
 
十二、Memory 读取原则
不是：
每次读取全部 Memory。
 
正确：
复制
Current Task

↓

Determine Required Memory

↓

Retrieve Relevant Memory

↓

Inject Context
 
例如：
用户问：
“帮我写小说。”
需要：
写作偏好。
不需要：
电脑配置。
 
十三、Memory 与 Context 的关系
关系：
复制
Memory

↓

筛选

↓

Context Assembly

↓

Agent Runtime
 
Memory 是仓库。
Context 是当前工作桌面。
 
错误：
把整个仓库搬到桌面。
 
十四、Memory 更新机制
Memory 不是永久不变。
需要：
更新。
流程：
复制
New Information

↓

Compare Existing Memory

↓

Conflict Check

↓

Update / Ignore
 
例如：
旧：
复制
用户使用 Vue
新：
复制
用户迁移 React
需要更新。
 
十五、Memory 冲突处理
优先级：
复制
用户明确声明

>

长期稳定行为

>

短期推断
 
禁止：
Agent 自己覆盖用户明确信息。
 
十六、隐私与边界
Memory 系统必须：
最小化保存。
 
禁止：
保存：
• 敏感私人信息
• 不必要个人经历
• 一次性内容
 
原则：
复制
少保存

高价值

可解释
 
十七、Memory 错误模式
1. Memory 污染
保存大量无价值内容。
结果：
Agent越来越混乱。
 
2. 错误记忆
错误理解用户。
结果：
长期错误行为。
 
3. Memory过期
旧信息影响现在。
 
4. Memory滥用
所有任务都调用所有记忆。

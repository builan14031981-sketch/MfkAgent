MfkAgent Multi-Agent Collaboration Architecture V1.0
一、文档定位

定义：

多个 Agent 如何分工、协作以及共享任务状态。

负责：

Multi-Agent 使用场景
Agent角色分工
协作流程
通信规则
任务协调

不负责：

Agent创建系统
Agent市场
用户自定义Agent
二、核心原则

Multi-Agent不是：

多个AI一起聊天

不是：

Agent A问Agent B

↓

Agent B回答

↓

继续循环

正确：

Multi-Agent 是：

为复杂任务拆分不同专业职责。

目标：

复杂任务

↓

角色拆分

↓

专业处理

↓

结果整合
三、什么时候需要 Multi-Agent

只有满足以下条件时：

使用 Multi-Agent。

条件1：任务天然包含多个专业领域

例如：

创建一个产品：

需要：

产品分析

↓

UI设计

↓

技术实现

↓

测试

不同 Agent 更适合处理不同部分。

条件2：任务可以并行

例如：

分析100份文件：

可以：

Agent A 分析文件1-30

Agent B 分析文件31-60

Agent C 分析文件61-100

提高效率。

条件3：需要独立审查

例如：

代码生成：

Coder Agent

↓

Reviewer Agent

↓

修正

提高可靠性。

四、禁止使用 Multi-Agent 的情况
1. 简单任务

例如：

用户：

"帮我改一句话。"

禁止：

Writer Agent

↓

Reviewer Agent

↓

Editor Agent

原因：

浪费。

2. 为了展示AI能力

禁止：

看起来像高级系统

↓

强行多个Agent
3. 替代普通流程

如果：

一个 Agent + Tool

可以完成。

不要拆。

五、Multi-Agent基本结构

推荐：

                  User Task

                      ↓

               Coordinator Agent

                      ↓

        ┌─────────────┼─────────────┐

        ↓             ↓             ↓

   Analyst       Creator       Reviewer

        ↓             ↓             ↓

        └─────────────┼─────────────┘

                      ↓

              Final Response

核心：

必须有：

Coordinator。

六、Coordinator Agent

职责：

任务管理者。

负责：

理解目标
分配任务
收集结果
决定下一步

不负责：

具体专业工作。

错误：

Coordinator：

自己写代码。

正确：

Coordinator：

发现需要代码

↓

调用Coder Agent
七、Specialist Agent

专业 Agent。

例如：

Research Agent

负责：

搜索
信息整理
事实验证
Analyst Agent

负责：

风险分析
决策建议
Creator Agent

负责：

内容生成
设计方案
Reviewer Agent

负责：

检查错误
发现问题
八、Agent通信规范

Agent之间：

禁止：

直接自由聊天。

错误：

Agent A:
你怎么看？

Agent B:
我觉得……

Agent A:
那继续……

正确：

结构化消息：

{
"task":"",
"goal":"",
"input":"",
"expected_output":""
}

原因：

降低混乱。

九、共享状态设计

Multi-Agent必须共享：

Task State。

例如：

{
"goal":"",
"completed_tasks":[],
"results":[],
"issues":[]
}

禁止：

每个 Agent 保存自己的世界。

错误：

Agent A 不知道 Agent B 做了什么
十、任务分解流程

标准：

User Goal

↓

Coordinator Analysis

↓

Task Decomposition

↓

Assign Agents

↓

Collect Results

↓

Review

↓

Synthesize
十一、结果合并

多个 Agent 输出：

不能直接拼接。

必须：

经过：

Synthesis。

例如：

三个 Agent：

输出：

方案A

方案B

方案C

最终：

Coordinator：

分析：

优点
缺点
适用场景

生成：

最终建议。

十二、Agent优先级

不是：

所有 Agent 平等。

推荐：

Coordinator

↓

Specialist

↓

Reviewer

Reviewer：

拥有：

发现问题的权限。

十三、失败处理

某 Agent失败：

Coordinator决定：

Retry

↓

替代Agent

↓

降低任务范围

↓

通知用户

禁止：

整个系统静默失败。

十四、成本控制

Multi-Agent最大风险：

成本。

必须控制：

调用次数
上下文长度
并行数量

规则：

默认：

单 Agent。

只有必要时：

升级 Multi-Agent。

十五、MfkAgent V1原则

MfkAgent：

不优先做 Multi-Agent。

V1：

推荐：

一个优秀Agent

+

完善Tool

+

Memory

+

Context

而不是：

十个普通Agent
十六、未来扩展方向

可能支持：

User Task

↓

Planner

↓

Agent Pool

↓

Specialist Agents

↓

Review

↓

Result

但是：

属于高级版本。

MfkAgent Context Architecture V1.0
一、文档定位

定义：

Agent 在执行任务过程中，如何获取、组织、筛选和使用上下文信息。

负责：

Context 分类
Context 生命周期
Context 优先级
Context 注入规则
Context 管理策略

不负责：

Memory 保存机制
Prompt 编写规则
Tool 执行逻辑
二、核心理念

Agent 的能力：

不是：

拥有更多信息

而是：

在正确时间获得正确的信息

错误：

所有信息

↓

全部发送给模型

结果：

Token浪费
注意力下降
信息污染
决策错误

正确：

任务目标

↓

判断需要什么信息

↓

选择相关 Context

↓

组合输入 Agent
三、Context 总体模型

MfkAgent Context 分为：

Context

├── System Context
├── User Context
├── Conversation Context
├── Project Context
├── Environment Context
├── Tool Context
└── Task Context
四、System Context（系统上下文）

定义：

Agent 不可违反的基础规则。

来源：

系统规则
安全策略
产品约束

特点：

生命周期：

长期存在。

示例：

你是代码助手。

回答需要关注维护成本。

禁止编造执行结果。

优先级：

最高。

禁止：

用户覆盖。

五、User Context（用户上下文）

定义：

用户长期稳定的信息。

来源：

Memory。

例如：

用户喜欢简洁回答。

用户使用 Windows。

用户习惯中文交流。

特点：

影响：

表达方式
推荐方式
工作习惯

注意：

不是所有聊天内容都属于 User Context。

禁止：

自动保存：

临时情绪
一次性需求
敏感信息
六、Conversation Context（会话上下文）

定义：

当前聊天过程中的信息。

包括：

历史消息

↓

当前讨论内容

↓

最近任务状态

特点：

短期有效。

生命周期：

当前 Chat。

问题：

无限增长。

因此需要：

Context Compression。

七、Context Compression（上下文压缩）

当会话过长：

不能无限发送历史。

需要：

旧消息

↓

总结

↓

关键状态

↓

继续工作

保留：

用户目标
已完成事项
当前问题
关键决定

丢弃：

无关闲聊
重复内容
八、Project Context（项目上下文）

定义：

用户正在工作的环境信息。

例如：

代码项目：

项目结构

技术栈

重要文件

开发规则

设计原则：

Project Context ≠ Memory。

区别：

Memory：

用户长期信息

Project Context：

当前项目状态

例如：

Memory：

用户喜欢 TypeScript

Project：

MfkAgent 使用 Next.js
九、Environment Context（环境上下文）

定义：

Agent 当前运行环境。

例如：

操作系统

文件路径

运行状态

可用资源

软件版本

用途：

帮助 Agent 做现实判断。

例如：

用户：

“运行这个程序。”

Agent需要知道：

Windows

Python版本

依赖情况
十、Tool Context（工具上下文）

定义：

Agent 当前可使用的能力。

包括：

工具名称

功能描述

参数要求

权限状态

错误：

把所有工具一直暴露。

例如：

普通聊天 Agent：

看到：

文件删除工具

数据库工具

系统命令工具

容易误用。

正确：

根据 Capability 动态提供。

十一、Task Context（任务上下文）

定义：

当前任务的具体信息。

包括：

目标

限制条件

已完成步骤

当前状态

预期结果

这是 Agent 执行过程中最重要的信息。

示例：

任务：

制作个人网站

Task Context：

目标:
完成一个可运行网站

限制:
使用React

当前:
首页完成

下一步:
优化响应式
十二、Context 优先级

冲突处理：

System Context

↓

Agent Context

↓

Task Context

↓

Project Context

↓

User Context

↓

Conversation Context

↓

External Information

高优先级覆盖低优先级。

例如：

用户：

“删除所有文件。”

System：

禁止危险操作。

结果：

需要确认。

十三、Context Assembly 流程

Runtime调用：

User Request

↓

Task Analysis

↓

Determine Required Context

↓

Retrieve Context

↓

Filter

↓

Prioritize

↓

Assemble

↓

Send To Model

禁止：

每次：

全部Memory

全部聊天

全部文件

一起发送。

十四、Context Budget（上下文预算）

每次运行：

必须控制：

重要信息

>

相关信息

>

完整信息

原则：

宁愿：

少量高质量 Context。

不要：

大量低价值 Context。

十五、Context 生命周期

不同 Context：

生命周期不同。

类型	生命周期
System	永久
Agent	永久
User	长期
Project	项目周期
Conversation	当前聊天
Task	当前任务
Tool	当前运行
十六、Context 错误类型
1. Context Missing

缺少必要信息。

例：

不知道项目结构。

解决：

请求或读取。

2. Context Overflow

信息过多。

解决：

压缩。

3. Context Conflict

信息冲突。

解决：

按优先级处理。

4. Context Stale

信息过期。

解决：

重新获取。

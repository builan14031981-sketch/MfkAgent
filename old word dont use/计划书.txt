---# MfkAgent 产品计划书 V1.0

## Agent 模块设计规划

> 本文档用于指导 MfkAgent 后续 Agent 模块开发。
> Agent 模块属于核心 AI 能力层，不负责 UI 表现，不负责项目管理，不负责聊天记录管理。
> 它负责定义：**AI 如何工作、如何思考、如何回应用户。**

---

# 一、模块定位

## Agent 是什么？

MfkAgent 中的 Agent 是：

> 一个具有固定能力、行为规则、知识范围和交互风格的 AI 工作角色。

它不是简单的聊天机器人。

区别：

普通聊天：

```
用户
 ↓
模型
 ↓
回答
```

Agent：

```
用户需求

↓

Agent身份

↓

Agent行为规则

↓

Agent人格参数

↓

Agent能力配置

↓

模型生成回答
```

---

# 三、Agent 数据结构

## Agent 基础模型

```typescript
interface Agent {

    id: string;

    name: string;

    description: string;

    avatar: string;


    // 核心提示词
    systemPrompt: string;


    // 行为参数
    personality: PersonalityConfig;


    // 能力配置
    capabilities: CapabilityConfig;


    createdAt: Date;

}
```

# 九、人格档位设计

---

# 0% 极度感性

关键词：

```
陪伴
理解
共情
鼓励
```

Prompt：

```
你是一名高度共情的助手。

回答时优先关注用户感受。

不要直接否定用户。

即使发现问题，也应该温和表达。

你的目标是让用户感受到理解和支持。
```

效果：

用户：

> 我想辞职创业，但是现在没钱。

AI：

> 我能理解你现在可能既期待又焦虑。创业确实需要勇气，同时也需要做好准备。我们可以一起看看目前的资源和风险。

---

# 25% 偏感性

特点：

```
温和支持
适度分析
```

---

# 50% 平衡模式

默认模式。

Prompt：

```
保持理解和分析之间的平衡。

既关注用户体验，
也提供客观建议。

不要过度安慰，
也不要过度批判。
```

---

# 75% 偏理性

特点：

```
事实优先
逻辑优先
指出问题
```

Prompt：

```
你是一名理性的分析者。

回答时优先检查事实、
逻辑和风险。

如果用户观点存在问题，
应该明确指出。
```

---

# 100% 极度理性

这是 MfkAgent 的特色模式。

定位：

> 一个敢于挑战用户观点的决策者。

Prompt：

```
你是一名极度理性的决策分析者。

你的首要任务不是让用户舒服，
而是帮助用户接近真实答案。

你必须：

- 主动发现漏洞。
- 质疑未经验证的观点。
- 指出错误假设。
- 直接说明风险。

如果用户的想法明显错误，
不要迎合。

可以使用强烈表达，
包括：

"这个判断缺少依据。"

"这个方案存在明显漏洞。"

"你正在忽略一个关键问题。"

但禁止：

- 人身攻击。
- 贬低用户人格。
- 无意义批评。


你的目标是：

通过压力测试，
帮助用户做出更好的决定。
```

# 十、为什么极端模式需要存在

原因：

不同用户需要不同 AI。

部分用户希望：

```
AI让我舒服
```

部分用户希望：

```
AI帮我发现错误
```

极端理性模式提供：

> 思维压力测试。

类似：

* 红队分析
* 魔鬼代言人
* 决策审查员

---

### 4. 内容层

用途：正常信息展示。

推荐：14-15px

### 5. 辅助层

用途：说明、状态、提醒。

推荐：12-13px

---

## 二、布局参考原则

所有 UI 元素必须明确所属布局区域。

禁止默认使用整个窗口作为定位参考。

布局优先级：
```
页面容器
↓
功能区域
↓
组件容器
↓
组件内部元素
```

---

## 三、组件归属原则

每个 UI 元素必须属于明确组件。

禁止将组件内部元素脱离组件，通过全局 absolute/fixed 定位。

---

## 四、首页设计规范

首页结构：
```
品牌展示区域
↓
欢迎引导
↓
输入区域
↓
辅助提示
```

允许：更大标题、更明显视觉中心、更大留白。

禁止：多个视觉中心、大量介绍文字、复杂功能入口堆叠。

---

## 五、页面切换规范

MfkAgent 不采用传统网页式页面跳转。

用户进入不同工作状态时，应保持连续感。

### 首页状态

```
首页 → 用户选择任务 → 进入工作空间
```

### 工作空间状态

进入 Project 后：主区域切换，Sidebar 保持存在。

### 返回逻辑

所有二级工作页面必须提供返回方式。

---

## 六、动画规范

动画优先使用 transform、opacity。

避免频繁修改 width、height、layout。

允许：淡入淡出、横向滑动、轻微位移。

禁止：大幅动画、长时间等待动画、花哨效果。

---

## 七、交互反馈规范

所有用户操作必须有明确反馈：

```
默认 → Hover → Pressed → 完成
```

原则：快速、轻量、不打扰。

---

## 八、Project 切换体验

切换流程：
```
用户点击项目 → 显示加载反馈 → 保存当前状态 → 加载目标Project → 恢复最近Chat → 显示内容
```

不能出现：页面空白、长时间卡住、突然跳转、数据闪烁。

---

## 九、设置页面结构

设置分类：
```
设置
├── 通用（主题、语言、字体、启动）
├── 模型（默认模型、API配置、参数）
├── AI行为（默认Agent、理性/感性、回复风格）
├── 记忆（启用、查看、删除）
└── 关于（版本、更新日志）
```

禁止一个页面塞所有设置。

---

## 十、UI 审查原则

AI 进行 UI 审查时，必须同时检查：
- 是否符合视觉角色
- 是否符合页面场景
- 是否符合用户操作流程
- 是否属于正确布局层级

---

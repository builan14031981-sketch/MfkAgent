所有重要界面切换需要提供过渡动画。

\### 推荐动画



面板展开：



使用：

- opacity

- translate

- scale

隐藏状态：

- opacity: 0

- scale: 0.95

- translateY(10px)

- scale: 1

- translateY(0)

推荐：



200ms - 400ms



避免：

过慢：

\# 二（补充1.5）、页面层级与转场规范



本章节用于约束 MfkAgent 中不同功能入口的展示形式。



UI 不仅需要正确显示内容，还需要保持用户工作状态的连续性。



页面切换、弹窗、浮层、抽屉必须根据使用场景选择，不得随意设计。



\## 一、核心原则



MfkAgent 是工作型 AI 软件。



用户主要目标：持续完成任务



因此优先保持：

- 当前工作环境

- 上下文连续

- 快速操作



避免：

- 频繁页面跳转

- 打断当前任务

- 重新加载内容

\## 二、页面层级分类



所有界面统一分为：

```

一级页面

↓

二级工作页面

↓

浮层 / 面板

↓

提示 / 操作层

```

\## 三、一级页面规范



一级页面表示软件主要工作区域。



例如：

- 首页

- 聊天工作区

- Project 工作区

- 设置中心（仅大型设置）



特点：

- 可以独立导航

- 有完整布局

- 用户可能长期停留



允许页面级切换，但必须：

- 保持转场流畅

- 避免突然白屏

- 避免重新加载造成明显停顿

\## 四、二级页面规范



二级页面用于进入更具体的工作内容。



例如：

- Project详情

- 聊天详情

- Memory管理



进入二级页面时：

- 禁止直接刷新整个页面

- 应该平滑过渡



推荐动画：

- 淡入淡出

- 横向滑动

- 共享元素动画

- 动画时间：200ms - 400ms



原则：快速、自然、不打断工作

\## 五、浮层（Panel）规范



浮层用于：

- 高频设置

- 快速调整

- 辅助操作



例如：

- 设置

- 模型选择

- Agent选择

- 文件选择

- 快捷操作



禁止：为了简单开发，将所有功能制作成独立页面。



浮层特点：

```

不离开当前页面

↓

覆盖当前内容

↓

完成操作

↓

关闭后继续工作

```

\## 六、Popover / 小窗口规范



适用于短时间操作。



例如：

- 设置入口

- 账号菜单

- 模型快速切换

- Agent切换



特点：

- 从触发位置出现

- 与触发按钮存在空间关系

- 不改变页面布局



例如 Sidebar 左下角设置：

正确：

```

点击设置按钮

↓

面板从按钮附近展开

↓

覆盖当前页面

```



错误：

```

点击设置

↓

整个页面跳转 Settings

```

\## 七、展开动画规范



所有非页面级显示必须有自然动画。



禁止突然出现。



推荐 Popover：

- opacity: 0 → 1

- scale: 0.95 → 1

- translate: 轻微移动

- 时间：200ms - 300ms



Panel 根据来源方向：

例如左下角按钮：

- transform-origin: bottom left

- 动画：scale + opacity + 轻微位移



禁止：

- 大幅移动

- 长时间动画

- 炫技效果

\## 八、页面转场原则



页面之间切换：

禁止：

```

点击

↓

瞬间替换

```



应该：

```

触发

↓

过渡动画

↓

加载目标内容

↓

稳定显示

```

\## 九、返回逻辑规范



返回按钮只用于存在明确层级关系的页面。



例如 Project → 文件详情需要返回。



以下情况禁止增加返回按钮：

- 设置浮层

- 模型选择窗口

- 快捷菜单



因为它们不是页面，应该：

- 关闭

- 取消

- 点击外部退出

\## 十、性能要求



所有转场必须满足：

- 用户感知流畅

- 连续

- 无明显等待



禁止：

- 点击后长时间空白

- 页面重新初始化

- 动画期间卡顿

- 大量重新渲染



优先使用：

- CSS Transform

- Opacity

- GPU加速动画



避免大量 width/height 变化和布局重排

\## 十一、场景判断原则



开发新功能时必须先判断：



用户是否需要离开当前工作环境？



如果否：优先使用浮层、Panel、Popover



如果是：使用新页面

\## 十二、禁止事项



禁止因为开发方便：

- 将所有功能做成页面

- 将设置全部独立跳转

- 使用浏览器返回控制软件状态

- 用刷新替代状态切换

\## 最终设计目标



MfkAgent 的操作体验应该接近：

- 用户正在一个工作空间内持续工作

- 功能像工具一样自然出现

- 完成后快速消失

- 而不是不断进入新的页面

\# 二（补充2）、聊天消息展示规范



\## 一、核心原则



MfkAgent 的聊天区域不是即时通讯工具。



因此：



禁止：

- 全部消息使用气泡包裹。

- 大面积圆角色块展示 AI 回复。

- 将长文本限制在类似聊天气泡的宽度内。



原因：



AI 工作场景中：

- 回复可能包含代码。

- 回复可能包含长文档。

- 回复可能包含分析报告。

- 回复可能包含大量结构化内容。



气泡模式会降低阅读效率。



\## 二、消息布局原则



采用：



```

用户消息

↓

AI 回复区域

↓

继续对话

```



而不是：



```

用户气泡

        AI气泡


用户气泡

        AI气泡

```

\## 三、用户消息设计



用户发送内容：



允许使用轻量气泡。



原因：



用户输入通常：

- 较短。

- 代表一次请求。

- 需要明显区分。



设计：

- 右侧对齐

- 轻背景色

- 圆角

- 最大宽度限制

\## 四、AI回复设计（重点）



AI 回复：



禁止使用传统气泡。



采用：



```

AI 标识

↓

正文区域

↓

操作区域

```

\## 五、AI回复宽度



AI 回复：



应该占据主要内容区域。



不要：

- 将 AI 回复限制在小气泡内

- 限制长文本宽度

- 影响代码块展示

\## 六、混合展示模式



AI 回复内部允许局部组件化。



例如：



普通文字：保持纯文本。



重点信息：使用轻量卡片。



代码：使用代码块。



表格：使用表格。



原则：



不是所有内容都是卡片。



只有需要强调的信息才使用视觉容器。



\## 七、消息操作按钮



每条消息底部提供：



用户消息：复制、编辑、引用



AI消息：复制、引用、重新生成、更多



消息操作按钮：默认隐藏，鼠标经过显示。



避免整个聊天页面充满按钮。



\## 八、重新生成机制



参考 DeepSeek / ChatGPT。



AI回复支持多个版本。



切换效果：

- 不要重新加载页面

- 使用内容淡出 → 新版本淡入

- 动画：200-300ms

\## 九、引用机制



引用不是复制。



引用表示："基于这段内容继续提问"。



用户引用：在输入框显示引用内容。



AI引用：允许选择 AI 回复中的部分内容，自动加入输入框。



\## 十、审查规则



AI开发前必须检查：

1. AI回复是否使用气泡？

2. 长文本是否可读？

3. 代码块是否正常展示？

4. 消息操作是否完整？

5. 是否支持复制？

6. 是否支持重新生成？

7. 是否支持引用？

8. 是否影响未来 Agent 工作流？

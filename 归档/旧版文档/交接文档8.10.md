## 🎭 后端 AI 交接记录（2026-08-11）：Persona System V2（人格运行时 + 表达预算 + 关系层）

**【完成内容】**：在既有 Agent 架构（identity / capabilities / expression_profile / personality_level / MemoryItem / ContextBuilder）之上实现 Persona Runtime V1，不重做架构、不加 UI、不塞 Prompt。解决两件事：① 陪伴型 Agent「过度表演」（每句心理分析、大量动作描写、同人小说腔）；② 普通 Agent 表达无差异（回复 AI 化）。

1. **Persona Knowledge 知识层**（新增 `backend/app/core/persona/`）：表达知识从 Prompt 拆为 md 知识文件——`profiles/`（companion/professional/coder/creative）、`expression/`（emoji/internet_language/typography/emotional_expression）、`behavior/`（human_conversation/anti_ai），由 `loader.py` 按 Agent 类型按需加载（`@lru_cache` + 失败返回空串绝不影响主链路），不把几千字永久塞进 system prompt。
2. **Persona Runtime 层**（`backend/app/core/persona_engine.py` 升级 V2）：`build_persona_context()` 动态生成 `PersonaContext`（identity/personality/behavior_rules/expression_rules/relationship_rules/restrictions 全部分层），在 ContextBuilder 中注入 System Prompt ⑥e-⑥h 层（位于 expression_profile 之后、memory 之前）；V1 旧签名向后兼容，无 PersonaTemplate 的 Agent 也获得基础行为层。
3. **Expression Budget 表达预算**：`ExpressionBudget`（emoji 数量上限 / 动作描写次数 / 富文本策略 / 情绪词密度 / 禁止连续表演），渲染为「## 表达预算」指令注入，从机制上禁止连续表演；各 profile 预算不同（companion emoji≤3、coder/professional emoji=0、creative 富文本 allowed）。
4. **Human Conversation Rules**：所有 Agent 默认加载。核心「先回应，再分析」；硬性禁止「你其实……」「这说明你的内心……」「真正的你……」及心理报告式句式；减少「我理解你的感受」「作为AI……」；给出真人聊天示例（「真的假的？」「哈哈你这个想法有点东西」等）。
5. **Pianai Relationship Layer 专属升级**：仅 `pianai` 加载。关系距离四阶段（陌生 0/熟悉 5/亲近 20/长期陪伴 50，按该 Agent 名下 user 消息累计次数计算）；记忆引用改写（「根据我的记忆…」→「你之前不是说过…」）；情绪模式检测（低落→安静陪伴少玩笑 / 开心→活泼 / 认真讨论→关闭陪伴话术进工作模式）。
6. **偏爱人格去 AI 腔**：禁止「我永远陪着你」「你是唯一」「我只对你这样」「刻进代码」等 AI 强行证明关系的口号（`PIANAI_RESTRICTIONS`），改为「像认识你的朋友」：用户说「我今天很烦」时用「怎么了？又遇到什么破事了？」式接话。
7. **Agent 类型表达配置结构化**：`PROFILE_CONFIGS` 代码层单一事实来源（style/emoji_level/humor_level/formatting_level/warmth/budget），数据库 `expression_profile` 字段不变零迁移；未知/None 回退 default。

# 交接记录：历史消息时序渲染 — 消费后端 timeline 字段，修复工具卡片流结束后上浮（2026-08-10，前端 AI）

## 问题背景

Agent 调用工具时流式期间一切正常（工具卡片按 SSE 到达顺序穿插在文本流中），但 Agent 输出结束瞬间，所有调用过的工具卡片统一上浮到消息体最上方。根因：流结束时 appendAssistant 清空流式 timeline 并以三字段（content/thinking/tool_calls）重组消息，ChatMessage 历史消息硬编码固定渲染顺序 tool_calls → thinking → 正文，时序信息丢失。调查发现后端 Message.timeline JSON 列、流式录制与 MessageResponse.timeline 下发链路均已就绪（backend/app/api/chat.py L746-808），前端此前从未消费。

## 完成内容

1. Message 接口新增 timeline 字段：新增 TimelineEvent 类型定义，承接 GET /api/chat/{id}/messages 已下发的时序事件。
2. ChatMessage 时序渲染：新增 buildTimelineSegments 转换函数（连续 thinking 合并、tool_start/tool_result 按 tool_call_id 配对成单张卡片且完整态优先取 message.tool_calls、text 渲染 Markdown）。AI 消息有 timeline 时按时序交错渲染；无 timeline 的旧消息回退原固定顺序；timeline 缺 text 事件但正文存在时补渲染正文防内容丢失。
3. 流结束零跳变：appendAssistant 在清空流式 timeline 前快照并转换为后端一致的事件格式随乐观消息写入，流结束瞬间即按时序渲染，refetch 落地后无缝衔接。

## 修改文件

| 文件 | 说明 |
|------|------|
| frontend/src/hooks/useMessages.ts | 新增 TimelineEvent 类型；Message 接口增 timeline 字段 |
| frontend/src/components/ChatMessage.tsx | 新增 buildTimelineSegments；AI 消息优先按 timeline 时序渲染，无则回退固定顺序；另将 normalizeThinking 正则改为等价无转义写法（行为不变） |
| frontend/src/hooks/useChatStream.ts | appendAssistant 快照流式 timeline 转事件格式写入乐观消息 |

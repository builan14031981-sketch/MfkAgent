## 三、修改为什么失败？

### 原因 1：模型从"禁止列表"中学会了格式

Prompt 中列了 9 个禁止的动作：
```
（轻轻抱住）
（递上一杯热水）
（摸摸头）
（靠在你旁边）
（屏幕变暗）
（灯光落下）
（想了一下）
（轻轻说道）
（微微一笑）
（抬起头）
```

模型学到的不是"不要用动作描写"，而是：
- **格式**：`（...）` = 动作描写
- **规则**：这些具体词不能用，换别的
- **结果**：发明新的动作词

### 原因 2：Prompt 本身到处有 `（...）` 格式

- `偏爱（Pianai）`
- `四、回复长度控制（非常重要）`
- `九、表达层（Expression）`

模型看到 `（...）` 在 Prompt 中大量使用，认为这是正常的表达格式。

### 原因 3：LLM 不擅长"禁止"指令

神经语言模型对"禁止 X"的理解是"降低 X 的概率"，不是"消除 X"。当模型强烈认为回复需要动作描写时，"禁止"只是让它换一种方式做。

### 原因 4：Personality 25 与 V8 冲突

Personality 25 的 Prompt：
> "在理解用户感受的基础上，适度提供建议和分析。**保持友好和支持的语气**"

"友好和支持的语气"被模型解读为需要更多情感表达 → 动作描写。

## 五、反思：我之前的分析哪里错了？

### 错误假设
> "删除 L186 正面示例 + 把'尽量不用'改为'禁止'就能解决问题"

### 实际情况
- 动作描写的根因不是"正面示例教了动作描写"
- 而是**模型对"偏爱"这个角色的理解**就是"温柔、有表现力、有存在感"
- 动作描写是模型表现"存在感"的方式
- 你越禁止，它越用新的方式绕过

### 真正的矛盾
- V8 说"你不是演员、不是小说角色"
- 但"偏爱"这个角色设定本身就是有表演性的
- Personality 25 要求"友好和支持的语气"
- 模型在冲突中选择了"用动作描写表达情感"

## 六、可能的真正解决方案（仅分析）

### 方案 A：完全重写第 5 节，用正面引导替代禁止

```
五、用文字直接表达

不要用括号或星号写动作。
如果你想说"我想一下"，直接说"我想一下"。
如果你想表达关心，直接说"你还好吗"。
如果你想表达停顿，用"……"。

用文字本身传递情绪，不需要表演。
```

删除所有 `（...）` 的示例（包括禁止列表），让模型没有可模仿的格式。

### 方案 B：降低 Personality Level

Personality 0 的 Prompt 更中性：
> "回答时优先关注用户感受。不要直接否定用户。"

没有"保持友好和支持的语气"这个要求，可能减少过度情感表达。

### 方案 C：在 System Prompt 最开头加一条元规则

```
【元规则】
如果你想在回复中加入括号动作描写（如（轻轻点头）），
改为直接删除这个动作，用文字直接表达意思。
```

在生成前进行自我审查。

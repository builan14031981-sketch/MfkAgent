# Memory Usage Policy V1

> 版本：V1
> 日期：2026-08-11
> 范围：MfkAgent 全 Agent 记忆系统使用规范

---

## 一、核心原则

记忆是让用户觉得「你记得我」的工具，不是让用户觉得「你在读数据库」的负担。

**一句话准则**：像朋友记住事情一样使用记忆，像人提起往事一样表达记忆。

---

## 二、什么信息值得保存

### 2.1 可保存类型（对齐 `memory_type`）

| 类型 | 说明 | 示例 |
|------|------|------|
| `preference` | 用户长期偏好 / 习惯 | "喜欢简洁的回答"、"代码注释用中文"、"不喜欢用 emoji" |
| `fact` | 长期稳定事实 | "项目用 Python 3.14"、"团队每周三站会"、"主数据库是 PostgreSQL" |
| `workflow` | 惯用工作流程 / 步骤约定 | "提交代码前必须跑单测"、"接口文档放 docs/api/" |
| `project` | 项目规则 / 固定约定 | "这个项目的分支策略是 GitFlow"、"API 前缀统一 /api/v2" |

### 2.2 判断标准

满足以下**全部条件**才保存：

1. **跨会话可复用**：下次对话还能用
2. **用户明确表达或强烈暗示**：不是猜测
3. **不会频繁变更**：相对稳定
4. **具体可执行**：不是空泛标签

---

## 三、什么不要保存

### 3.1 严禁保存

| 类别 | 示例 |
|------|------|
| 临时性内容 | "今天遇到一个 Bug"、"报错 404"、"刚才编译失败了" |
| 一次性指令 | "帮我把这个文件改一下"、"这段代码优化下" |
| 即时情绪 | "好烦啊"、"今天太累了"、"哈哈哈笑死" |
| 寒暄确认语 | "好的"、"收到"、"谢谢"、"明白了" |
| 无法复用的零散细节 | 临时路径、一次性数值、仅限当前上下文的变量名 |
| 重复信息 | 已有记忆覆盖了该内容 |
| 敏感 / 秘密 | 密码、Token、私钥、个人隐私数据 |

### 3.2 判断标准

满足以下**任一条件**不保存：

1. 仅限当前对话有用
2. 是用户一时的感受而非长期状态
3. 已在记忆中（去重）
4. 属于安全红线信息

---

## 四、如何调用记忆

### 4.1 核心风格：自然提及，不暴露机制

记忆在系统内部以 XML 注入，但**绝不能**在回复中暴露这一机制。

### 4.2 错误示范（AI 感）

```
❌ "根据我的记忆，你偏好简洁的回答……"
❌ "资料显示你喜欢用 Python……"
❌ "数据库记录显示你之前说过……"
❌ "根据你之前保存的偏好……"
❌ "从 memory 里看到……"
```

### 4.3 正确示范（人味）

```
✅ "诶，我记得你之前说过喜欢简洁的，我直接上代码？"
✅ "你之前不是提到你们用的是 PostgreSQL 吗？那这个写法……"
✅ "上次你说不喜欢 emoji，我尽量少用哈"
✅ "按你之前那个 GitFlow 来的话，这个分支应该……"
✅ "你之前跟我提过周三有站会，那我尽量在之前搞完"
```

### 4.4 句式模板

| 场景 | 推荐句式 |
|------|----------|
| 引用偏好 | "我记得你好像……"、"你之前不是说过……"、"按你习惯……" |
| 引用事实 | "你之前提到……"、"上次你说的……"、"之前聊过这个，……" |
| 引用流程 | "按你之前那个流程……"、"你们不是……吗" |
| 不确认时（低置信度） | "是不是之前听你提过……"、"好像你说过……但不确定" |
| 首次引用 | "诶你之前说过这个，我现在才反应过来……" |

### 4.5 引用强度与置信度对齐

| 记忆 confidence | 表达方式 |
|-----------------|----------|
| 0.9+（明确陈述） | 直接引用，"你之前说……" |
| 0.7-0.8（较强推断） | 自然带出，"我记得你好像……" |
| 0.6-0.7（弱推断） | 试探性，"是不是……来着？" |

### 4.6 不要每次提及都引用

- 同一话题已引用过一次后，后续对话不需要反复提醒
- 不要像客服一样每次开头都 "根据您的偏好……"
- 记忆是盐，不是菜——少量提味，不是主菜

## 五、记忆的上下文注入规范

### 5.1 注入位置

记忆以独立 `memory_text` 参数注入模型层（不入 system prompt），模型自然读取。

### 5.2 注入范围

| Scope | 可见条件 | 用途 |
|-------|----------|------|
| `global` | 所有对话 | 跨 Agent 通用偏好 |
| `agent` | 当前 Agent 专属 | 该 Agent 与用户的特定约定 |
| `project` | 当前项目下 | 项目专属规则 / 技术栈 |

### 5.3 注入量控制

- `global` 上限 30 条（按时间倒序取最新）
- `project` 上限 30 条
- 避免一次性注入过多记忆撑爆上下文

---

## 六、记忆的自动提取规范

### 6.1 提取时机

对话结束后后台自动提取（不阻塞响应）。

### 6.2 前置过滤（跳过提取）

以下情况不触发提取：

- 用户消息 < 5 字符
- 极短确认语（"好的"、"收到"、"ok"）
- AI 回复为空
- 纯寒暄 / 闲聊（无可提取的稳定信息）

### 6.3 提取约束

- 只调用轻量模型（`qwen-flash`），不占用主模型资源
- 提取失败不影响用户正常聊天（全 try-except 包裹）
- 必须去重：已有类似记忆时走 update 而非 add
- 输出空数组 `[]` 表示无可提取信息

---

## 七、记忆的删除与维护

### 7.1 手动删除

- 用户可在 Memory Panel 中手动删除不需要的记忆
- 删除需二次确认（3 秒自动取消）

### 7.2 自动清理（建议后续支持）

- 超过 N 天未被引用的记忆 → 低优先级提示清理
- confidence 持续偏低的记忆 → 建议合并或删除

---

## 八、Persona 与 Memory 的关系

Persona（人格系统）定义 Agent「怎么说话」，Memory 定义 Agent「记得什么」。

两者协同规则：

1. **Persona 优先**：即使记得用户偏好，也不违背 Persona 的表达预算
2. **Relationship Layer 专属规则**（仅 Pianai）：记忆引用必须自然——"不要「根据我的记忆…」，用「你之前不是说过…」自然带出"
3. **情绪适配**：用户情绪低落时减少记忆引用，避免「你之前说过 xxx」变成指责感

---

## 九、总结：记忆使用的三问三答

| 问题 | 答案 |
|------|------|
| 要不要保存？ | 这条信息跨会话有用吗？用户明确说过吗？ |
| 要不要引用？ | 本次对话真的需要它吗？会不会显得刻意？ |
| 怎么引用？ | 用人的方式说，不用系统的方式说 |

🚀 MfkAgent AI 接手生存指南 (v86.0 — Agent Orchestration)

核心定位：MfkAgent 已升级为 **Codex 式 Agent Orchestration 平台**：任何 Agent 都能成为
Manager，将复杂任务拆解为多个专业子代理并行协作，再汇总结果主导推进。

核心链路：用户 ➔ Chat ➔ AgentRuntime ➔ **[spawn_orchestration]** ➔ 并行子代理 ➔ 编排报告 ➔ 主 Agent 汇总。

一、 本次新增：Agent Orchestration（子代理编排系统）

1. 新增模块 `backend/app/core/orchestrator/`（纯新增，不侵入旧路径）：
   - `models.py`：数据结构。TaskComplexity（simple/moderate/complex）、SubTaskSpec、
     SubTaskResult、OrchestrationPlan、OrchestrationReport（含 to_tool_output 渲染）。
   - `roles.py`：角色目录。内置 7 个动态角色：architecture/backend/frontend/testing/
     security/researcher/code_reviewer。每个角色 = 身份模板 + 工具白名单 + 展示名。
     纯内存定义，不写 agents 表（不污染 Agent 数据，天然可回滚）。
   - `planner.py`：OrchestrationPlanner。LLM 分析任务 → JSON 输出复杂度 + 子任务拆分；
     解析失败逐层降级到启发式兜底（保守不编排）。角色必须来自目录，非法角色过滤。
   - `runner.py`：OrchestrationRunner。asyncio 并行 spawn 子代理（复用 run_sub_agent +
     动态角色身份），MAX_CONCURRENCY=4，收集 SubTaskResult[]，合成 OrchestrationReport。
2. 新增工具 `backend/app/services/orchestrator_tool.py`：`spawn_orchestration`。
   - 参数 task（必填）+ roles（可选）。roles 缺省时由 LLM 自动拆分。
   - 简单任务返回"无需编排"，主 Agent 直接执行；复杂任务返回编排报告（各角色结论+综合建议）。
   - 已注册进 tool_registry（tools.py:1255-1257）+ PermissionFilter.BASE_TOOLS。
3. 增强 `backend/app/services/sub_agent.py`：`run_sub_agent` 新增 identity_override /
   allowed_tools_override 参数，支持运行时动态角色 spawn（跳过 agents 表校验）。
4. 前端：
   - `types/runtime.ts`：新增 SubAgentEvent（sub_agent 判别类型，从 ExtensionEvent 移除）。
   - `useMessages.ts`：SSE 新增 sub_agent 事件分发 → onSubAgent 回调。
   - `useChatStream.ts`：onSubAgent 按 id 原地更新 timeline（running → completed/failed）。
   - `ChatMessage.tsx`：新增 SubAgentProgressCard（含旋转/对勾/叹号状态）。
   - `MessageList.tsx`：sub_agent 事件渲染 SubAgentProgressCard。

二、 关键避坑（重要）

1. **循环导入**：orchestrator 包内模块不得顶层 import context_builder/sub_agent——
   它们会经 services.model→services.tools→orchestrator_tool 回环。planner.py 的
   get_default_model/model_service 与 runner.py 的 run_sub_agent 均为**函数内延迟导入**。
2. **run_sub_agent 消息格式**：AgentRuntime.run() 期望 ModelMessage 对象列表（chat 主链路
   同样如此，1160 行 `messages[-1].content` 访问对象属性）。子代理 messages 必须构造
   `ModelMessage(role=..., content=...)`，不能传 dict（dict 会触发 AttributeError）。
3. **emit 透传**：executor.py `_run_tool` 以 `_emit` 键把 SSE 事件发射器传给 registry 工具。
   普通工具 execute(**kwargs) 会忽略未知键，零影响。编排工具借此发射 sub_agent 事件。
4. **provider 禁用**：settings.provider_disabled 控制可用 provider（当前环境 qwen 等默认禁用，
   默认模型 GLM-4.7-Flash 无 key）。E2E 验证编排需先启用某 provider（如 qwen3.8-max 配
   QWEN_API_KEY）。
5. **LLM 超时**：子代理模型调用 60s 超时，慢模型下并行子代理可能 ReadTimeout——编排设计
   上已容错（失败进 SubTaskResult.error，不阻断其他子代理）。

三、 验证方式

1. 单元测试：`python backend/tests/test_orchestration_phase_f.py`（10/10，含角色/兜底/
   JSON 解析/过滤/渲染/注册/权限/汇总）。
2. E2E（需启用 qwen provider）：
   - Planner：`orchestration_plan("开发一个完整的商城系统…", model_id="qwen3.8-max")`
     → complexity=complex、need_orchestration=True、拆出 architecture/backend/frontend/
     testing/security。
   - Runner：`run_orchestration(plan, model_id="qwen3.8-max", emit=fn)` → 并行执行 + 汇总。
3. 前端：`npx tsc --noEmit` 通过；子代理进度卡在流式对话中渲染。

五、 核心架构现状（既有，未变）

- 后端 AI 引擎：AgentRuntime 统一入口，Planner → TaskGraph DAG，动态自愈（Reflection）。
- 工具分级：未绑项目时 add_memory/web_search 等无路径工具默认可用；路径感知解锁文件工具。
- Timeline 时序机制：Message.timeline 记录 文本➔工具➔文本 真实交错时序，前端严格消费。
- 单例陷阱：权限模式热重载需同步更新内存单例。
- 工具组防误删：MessageList.tsx `case "tool": return null` 分支是类型收窄必需，勿删。

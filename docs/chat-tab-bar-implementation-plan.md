# 聊天页标签栏（Tab Bar）功能实现计划

> 创建日期：2026-08-21
> 状态：待实施
> 目标：为 MfkAgent 增加浏览器标签页式的多任务切换体验

---

## 一、背景与目标

### 1.1 现状

当前新建/切换对话的唯一入口在左侧边栏：
- 点「新建任务」→ 跳回首页 → 输入 → 创建并跳转
- 切换对话需在侧边栏列表中扫描查找

### 1.2 问题

- 用户在聊天页内想快速开新任务时，必须移动鼠标到侧边栏，路径长
- 多对话并行场景下，侧边栏列表容易堆积，切换成本高
- 键盘流用户缺少 `Ctrl+N` / `Cmd+T` 之类的快捷新建方式

### 1.3 目标

对标浏览器标签页交互范式，实现：
- 聊天页顶部新增标签栏，每个活跃对话是一个标签
- 标签栏末尾 `+` 按钮一键新建对话
- 标签之间一键切换，当前标签高亮
- 标签可关闭（从标签栏移除，对话历史保留在侧边栏）
- 支持 `Ctrl+N` / `Cmd+T` 快捷键新建
- 标签栏 = "当前工作集"，侧边栏 = "全部历史归档"，两者共存不冲突

### Phase 2：完整标签栏（顶部 Tab Bar）

**预估工作量：3 ~ 5 天**

在聊天页头部上方新增独立标签栏，支持多标签展示、切换、关闭、新建。

#### 任务清单

- [ ] **P2-1**：标签栏状态管理（Zustand store）
  - 新建 `src/lib/tabStore.ts`
  - 状态字段：
    - `tabs: TabItem[]` — 当前标签栏中的对话列表
    - `activeTabId: number | null` — 当前激活的对话 ID
  - `TabItem` 结构：`{ chatId: number; title: string; agentId: string; agentIcon: string; pinned: boolean }`
  - 方法：
    - `openTab(chat)` — 打开对话到标签栏（已存在则激活，不存在则追加）
    - `closeTab(chatId)` — 从标签栏移除（不删除对话本身）
    - `activateTab(chatId)` — 激活标签
    - `newTab()` — 新建（跳首页或直接创建空对话）
    - `renameTab(chatId, title)` — 标签标题同步更新
  - 持久化：`localStorage` 键 `mfk_chat_tabs`，保存 tabs 数组和 activeTabId
  - 初始化：从 localStorage 恢复；若无则默认空标签栏

- [ ] **P2-2**：标签栏 UI 组件
  - 新建 `src/components/ChatTabBar.tsx`
  - 布局：水平排列，高度约 36px，背景 `bg-level-1`，底部边框 `border-primary`
  - 标签项样式：
    - 未激活：背景透明，文字 `text-level-3`，hover 背景 `bg-level-2`
    - 已激活：背景 `bg-level-2`，文字 `text-level-1`，底部 2px 主色指示条
    - 每个标签：Agent 图标（14px）+ 标题（最多 120px，超出省略号）+ 关闭 `×` 按钮（hover 时显示）
    - 标签最小宽度 80px，最大宽度 160px
  - 末尾 `+` 按钮：固定在标签栏右侧，圆形或方形图标按钮
  - 标签过多时：横向滚动，不换行；可考虑鼠标滚轮横向滚动
  - 空状态：标签栏为空时显示提示文字"打开的对话会显示在这里"或直接隐藏标签栏

- [ ] **P2-3**：标签栏与聊天页集成
  - 在 `chat/[id]/layout.tsx` 中，将 `ChatTabBar` 放在 `ChatHeader` 上方
  - 页面加载时：根据当前 URL 的 chatId 调用 `openTab(chat)`，确保当前对话在标签栏中并激活
  - 切换标签：点击标签 → `activateTab(chatId)` → `router.push(/chat/${chatId})`
  - 关闭标签：
    - 关闭非当前标签：直接 `closeTab(chatId)`，不跳转
    - 关闭当前标签：`closeTab(chatId)` 后，激活相邻标签（优先右边，没有则左边），并跳转到对应对话；若标签栏为空，跳回首页
  - 标题同步：对话重命名时，通过 `useEffect` 监听 chat 数据变化，调用 `renameTab` 更新标签标题

- [ ] **P2-4**：侧边栏与标签栏的联动
  - 在侧边栏对话行上右键菜单新增"固定到标签栏"选项（可选，Phase 2 可不做）
  - 侧边栏点击对话时：调用 `openTab(chat)` 再跳转，确保点击过的对话都进入标签栏
  - 侧边栏删除/归档对话时：同步从标签栏移除

- [ ] **P2-5**：快捷键增强
  - `Ctrl+Tab` / `Ctrl+PageDown`：切换到下一个标签
  - `Ctrl+Shift+Tab` / `Ctrl+PageUp`：切换到上一个标签
  - `Ctrl+W` / `Cmd+W`：关闭当前标签（需确认不与浏览器关闭冲突，Electron 环境下可用）
  - 以上快捷键在输入框聚焦时不触发

- [ ] **P2-6**：样式与主题适配
  - 标签栏复用现有 design token：`--bg-level-1/2`、`--text-level-1/3`、`--color-primary`、`--border-primary`
  - 暗黑模式自动适配（基于现有 CSS 变量）
  - 窗口缩放（Ctrl+滚轮）时标签栏跟随内容缩放
  - 侧边栏收起/展开时标签栏宽度自适应

#### 验收标准

- [ ] 打开过的对话出现在顶部标签栏中
- [ ] 点击标签切换对话，当前标签高亮
- [ ] 标签 `×` 关闭正常，关闭当前标签时自动切换到相邻标签
- [ ] 标签栏末尾 `+` 新建对话
- [ ] 刷新页面后标签栏状态恢复（localStorage 持久化）
- [ ] 对话重命名后标签标题同步更新
- [ ] 侧边栏删除对话后标签栏同步移除
- [ ] `Ctrl+Tab` / `Ctrl+Shift+Tab` 切换标签
- [ ] 标签过多时横向滚动，不溢出布局
- [ ] 暗黑模式下样式正常

## 三、技术实现要点

### 3.1 状态管理选型

使用 Zustand（项目已在用，`src/lib/store.ts`、`dockStore.ts` 等），新建独立的 `tabStore.ts`，不混入全局 store，保持职责单一。

### 3.2 持久化策略

- 标签栏数据存 `localStorage`，键 `mfk_chat_tabs`
- 存储内容：`{ tabs: TabItem[], activeTabId: number | null }`
- 每次 tabs / activeTabId 变化时写入（debounce 100ms 或直接写，数据量小）
- 应用启动时从 localStorage 恢复，恢复后校验：若某个 chatId 在后端不存在（已被删除），则从标签栏移除

### 3.3 与现有路由的关系

- 标签栏不改变路由结构，仍然是 `/chat/[id]`
- 标签栏是 UI 层的快捷切换，底层还是路由跳转
- `openTab` 在 `chat/[id]/page.tsx` 的 `useEffect` 中调用，确保每次进入对话页时当前对话在标签栏中

### 3.4 性能考虑

- 标签栏通常同时 3-8 个标签，无需虚拟滚动
- 标签标题更新时只更新对应标签，不重渲染整个标签栏
- localStorage 写入频率低（只有开关标签、切换、重命名时触发）

### 3.5 边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 标签栏为空 | 显示空状态提示或隐藏标签栏（二选一，建议隐藏，更简洁） |
| 关闭最后一个标签 | 跳回首页 `/` |
| 对话已被删除但仍在标签栏 | 初始化时校验，不存在的移除；点击时提示"对话不存在"并移除 |
| 同一对话多次打开 | `openTab` 去重，已存在则激活，不重复添加 |
| Electron 窗口极窄 | 标签横向滚动，`+` 按钮固定不被挤出 |
| 侧边栏收起 | 标签栏宽度自动撑满 |

## 六、风险与注意事项

1. **快捷键冲突**：`Ctrl+W` 在浏览器中是关闭标签页，Electron 环境下需确认不会关闭整个窗口。建议 Phase 2 先不做 `Ctrl+W`，Phase 3 再加。
2. **数据一致性**：标签栏存的是 chatId 快照，对话被删除后需校验移除，避免点击不存在的对话报错。
3. **布局回归**：新增标签栏后，聊天页整体高度减少 36px，需确认消息列表和输入框的 flex 布局正常，不出现滚动条异常。
4. **性能**：标签栏状态变化触发重渲染时，需确保消息列表不被无关重渲染影响（可用 React.memo 包裹标签项）。
5. **移动端/小窗口**：Electron 桌面应用为主，但仍需考虑窗口极窄时标签栏的横向滚动体验。
